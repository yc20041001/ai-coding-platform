# Milestone 36D: Patch Proposal Artifact

## 1. 背景

Milestone 36A-36C 已完成工具安全执行基础链路：

- 36A: Safe Tool Execution Sandbox
- 36B: Read-only Tool Catalog + Tool Policy
- 36C: Human-approved Tool Execution

当前系统已经支持：

```text
Tool Catalog -> Project Tool Config -> Tool Policy -> WAITING_APPROVAL -> approve / reject -> Mock execution
```

36C 中引入了 HIGH 风险工具 `MOCK_PATCH_PROPOSAL`，但审批通过后仍只停留在 tool execution output 中。为了让结果更像可交付物，需要将高风险工具的 Mock 输出沉淀为正式任务产物。

Milestone 36D 的目标是新增 **Patch Proposal Artifact**：

```text
MOCK_PATCH_PROPOSAL approved
  -> Mock execution COMPLETED
  -> generate PATCH_PROPOSAL artifact
  -> frontend preview diff-like content
  -> no file write
  -> no git apply
```

本阶段仍不执行真实 shell，不做 Git 写操作，不写真实代码文件，不应用补丁。

## 2. 总目标

实现“补丁提案产物”基础闭环：

1. 新增任务产物类型 `PATCH_PROPOSAL`。
2. `MOCK_PATCH_PROPOSAL` 审批通过并 Mock 执行后生成 Patch Proposal Artifact。
3. Artifact 内容使用 diff-like markdown 格式。
4. Artifact 明确标记“仅提案，未应用”。
5. 前端 Task Artifacts 可展示 Patch Proposal。
6. MultiAgentRunPanel 工具卡片可关联 Patch Proposal Artifact。
7. 后端测试证明没有文件写入和 Git 操作。
8. 前端 E2E 覆盖审批后产物可见。

完成后，工具链从：

```text
High-risk tool approved -> Mock output
```

升级为：

```text
High-risk tool approved -> Mock output -> Patch Proposal Artifact
```

## 3. 严格边界

必须遵守：

1. 不执行真实 shell。
2. 不执行真实 Git 写操作。
3. 不执行 `git diff` / `git apply` / `git add` / `git commit`。
4. 不写真实代码文件。
5. 不创建真实 patch 文件到 workspace。
6. 不修改 Repository 模块已验证逻辑。
7. 不做真实代码生成。
8. 不做 patch apply。
9. 不做 PR comment。
10. 不接真实 IDE / 编辑器。
11. 不破坏 36A/36B/36C API。
12. 不破坏 Task artifact 原有查询接口。
13. 不绕过审批流程。
14. 前端保持中文暗色科技风 UI。

允许做：

- 新增 artifact type 枚举值。
- 生成数据库里的 task artifact 记录。
- artifact.content 保存 diff-like markdown。
- 前端展示和预览 artifact。
- Tool execution response 关联 artifactId。

## 7. Patch Proposal 内容格式

Artifact content 必须是 markdown，包含：

```markdown
# Patch Proposal: <task title>

> 安全提示：这是 Mock 补丁提案，仅用于审阅。系统没有写入文件，没有执行 git apply，没有提交代码。

## Summary

- Proposed change: ...
- Generated by tool: MOCK_PATCH_PROPOSAL
- Execution mode: MOCK_EXECUTE
- Files touched: 0
- Git operations: 0

## Proposed Diff (Mock)

```diff
diff --git a/src/example/ExampleService.java b/src/example/ExampleService.java
--- a/src/example/ExampleService.java
+++ b/src/example/ExampleService.java
@@ -1,5 +1,8 @@
 public class ExampleService {
+    // Mock proposal only. Not applied.
 }
```

## Review Checklist

- [ ] Confirm proposal matches task requirements
- [ ] Confirm no sensitive data is included
- [ ] Confirm no real file was modified
- [ ] Decide whether to manually implement in a future step

## Safety

- mock: true
- filesTouched: []
- gitOperations: []
- applied: false
```

注意：

- 不要包含真实绝对路径。
- 不要包含 API Key / token。
- 不要包含用户本地路径。
- diff 内容必须是 Mock 示例。

## 8. 后端服务设计

新增：

```text
backend/src/main/java/com/aicoding/platform/orchestration/application/PatchProposalArtifactService.java
```

职责：

```java
public AiTaskArtifactEntity createPatchProposalArtifact(
    ToolSandboxExecutionEntity execution,
    AiTaskEntity task,
    String mockOutput
)
```

行为：

1. 校验 toolName = MOCK_PATCH_PROPOSAL。
2. 校验 execution.status = COMPLETED。
3. 构造 markdown content。
4. 插入 ai_task_artifact：
   - artifactType = PATCH_PROPOSAL
   - name = `Mock Patch Proposal - <task title>`
   - content = markdown
5. 返回 artifact。

## 9. ToolSandboxExecutionService 集成

修改 36C 的 approve flow：

```text
approveAndExecute(executionId)
  -> approval APPROVED
  -> execution COMPLETED
  -> if toolName == MOCK_PATCH_PROPOSAL:
       create PATCH_PROPOSAL artifact
       execution.artifactId = artifact.id
       outputPayload.artifactId = artifact.id
  -> write task log PATCH_PROPOSAL_CREATED
```

任务日志：

```text
level: INFO
stage: PATCH_PROPOSAL_CREATED
message: Mock Patch Proposal 产物已生成，仅供审阅，未应用到文件系统。
```

outputPayload 增强：

```json
{
  "mock": true,
  "readOnly": true,
  "applied": false,
  "artifactId": "123",
  "filesTouched": [],
  "gitOperations": [],
  "safety": "Proposal only. No real file or git operation was executed."
}
```

## 17. 验收标准

- `TaskArtifactType.PATCH_PROPOSAL` 存在。
